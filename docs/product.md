# さくるん — プロダクト定義

## コンセプト
サークルの記憶を持つAIエージェント「さくるん」。
連絡も、振り返りも、引き継ぎも、同じ記憶の上で動く。

## 目的
サークル管理に必要な業務をAIで最適化し、運営コスト（幹部の負担）を軽減・削減する

## ターゲットユーザー
- サークルの幹部（運営メンバー）
- 一般部員（掲示板・連絡を受け取る側として関わる）

## 課題・ニーズ
- サークル運営には連絡文作成、日程調整、タスク依頼、外部団体・企業とのやり取り、引き継ぎなど雑務が多く、幹部の負担が大きい
- 運営に必要な知識（イベントの決定事項、相手ごとの付き合い方、過去の反省）が個人の頭の中に溜まり、共有も引き継ぎもされない
- 汎用チャットAIに頼んでも、サークル固有の文脈を知らないため、毎回説明し直すことになる

## プロダクトの構造：「記憶」×「動詞」

### 基盤：サークルの記憶（文脈ストア）
汎用チャットAIとの差別化点。スキーマで縛らない自由記述で蓄積し、画面上で編集して育てる。

| 記憶 | 実体 | 例 |
|---|---|---|
| 人の記憶 | 宛先マスタ＋書き方メモ、メンバーデータ | 「窓口は委員長の山本さん。返信は2〜3日かかる」「月火は授業で忙しい」 |
| 活動の記憶 | プロジェクト＋ノート | 「開催日は9/12、会場はA大学ホール」「協賛はロゴ掲載が条件」 |
| 教訓の記憶 | 振り返り（KPT） | 「告知が前日になり参加率が低かった。次回は1週間前に」 |

### UseCase：記憶を使う動詞
記憶の上で動く個々のタスク。連絡文作成はその一つに過ぎない。

| 動詞 | 内容 | 状態 |
|---|---|---|
| 伝える | 宛先ごとの書き方メモに従い、複数宛先へ一括で連絡文を下書き。5W1Hの不足も指摘 | 実装済み（デモの主役） |
| 振り返る | ノートと実際に送った連絡からKPTドラフトを生成。保存した教訓は以後の全生成に反映 | 実装済み |
| 引き継ぐ | プロジェクトのノート＋振り返りをNotionへ書き出して長期保管 | 実装済み（簡易版） |
| 調整する | 日程調整・Googleカレンダーへのイベント登録 | ストレッチ（未完） |
| 割り当てる／募る／管理する | タスク分配、SNS・新歓告知、備品管理など | 将来枠 |

### すべての動詞に共通する型
> 記憶を読む → AIがドラフト → 人間が編集・確定（Human-in-the-loop） → 実行 → 結果が記憶に還る

最後の「記憶に還る」がこのプロダクトの本質。**使えば使うほど記憶が濃くなり、すべての動詞が賢くなる**（PDCAの環）。
AIのアウトプットは必ず人間の確認・編集を経てから確定する。外部宛の送信そのものは人間が行う。

## 代表ユースケース：同じ状況を複数の相手に同時に説明する
例：合同ハッカソンの日程が1週間ずれ込みそう
- 部長へはLINEで率直に1〜2文の相談
- 他大学の実行委員会へはメールでフォーマルな調整依頼
- 協賛企業へはビジネスメール形式の丁寧な連絡

状況を1回書くだけで、記憶（ノートの日付・会場・担当者名、宛先ごとの書き方メモ）を反映した下書きがまとめて出る。

## 対象外（今回は作らない）
- SNSアカウントのパスワード・権限管理機能
- 部員ごとのGoogleアカウント個別連携（OAuth）
- 実際のメール/LINE送信API（確定後の送信は人間が行う）

## 成功の定義（デモゴール）
- 状況を1回書くだけで、複数の宛先に書き分けた下書きがまとめて生成され、蓄積した記憶の事実（日付・会場・担当者名）が推測でなく文面に反映される
- 振り返りを保存すると次の下書き生成に教訓が活きる、という「記憶に還る」環が一周する様子を見せられる
